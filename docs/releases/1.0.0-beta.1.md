# 1.0-beta-1

This beta replaces persistent per-MCP Node relays with a lightweight native relay and a Rust worker supervisor. Local workers start when needed; initializing a client and discovering tools can leave no resident worker. Stateful sessions remain isolated.

- Stop and Resume work from each MCP card, the tray and the CLI. Stopping preserves definitions and sign-ins.
- Worker admission reserves discovery capacity, limits concurrent residents and bounds request queues. Each worker exposes its client, process count and memory use.
- Windows workers enter strict kill-on-close Job Objects before execution. macOS adds marked descendant tracking and a supervisor lifeline. External applications should be attached through their existing connection endpoints.
- Native relays support simultaneous requests and replies over Windows named pipes and macOS sockets. Worker restarts replay the MCP initialization handshake and client roots.
- The endpoint library separates 20 generic defaults from private custom definitions. Existing definitions, keys, model caches and profile references survive migration.
- Protocol choices are OpenAI Chat Completions, OpenAI Responses and Anthropic Messages. Native Responses streams preserve their event framing; conversion routes reject unsupported stateful features explicitly.
- macOS sync includes all supported clients. Closing the dashboard leaves the menu-bar manager available and hides the Dock icon.

Saved API keys remain in the operating-system-protected vault. Encrypted Sharing carries referenced portable keys and sign-ins; installation packages contain no configured accounts, agent profiles, keys or notification topics. Localhost endpoints still require a model server on each device.

Validation includes 37 focused tests on Windows and macOS, TypeScript checking, native worker cleanup and relay transport fixtures, local HTTP streaming fixtures, installed-app discovery and Stop/Resume checks, and an independent confidentiality review of source and decoded packages. No paid inference or new OAuth consent was used. These checks do not establish every provider's permissions or every external client's behavior.

Before replacing an existing macOS app with a different signing identity, preserve its app, vault and generated client configurations. Migrate credentials through the existing app while it can still access its Keychain, then verify reads using the replacement in the graphical login session. Ad-hoc signed macOS packages are not notarized.
