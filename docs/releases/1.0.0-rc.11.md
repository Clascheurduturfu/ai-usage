# AI Usage 1.0.0 RC 11

Release candidate for 1.0.0 lifting the MCP worker pool cap and making the agent sync review readable.

## MCP pool

- **No more "Pool saturated"**: the native supervisor ([mcp_native.rs](../../src-tauri/src/mcp_native.rs)) refused a 9th worker, a 7th stateful worker, or a 3rd worker for the same server. With several agent sessions open, servers such as kanzo, memory or chrome-devtools failed to start with `-32000 Pool saturated`. The cap was the same on Windows and macOS. Only a runaway guard of 256 workers remains.

## Agent sync review

- **Each file says what it will do**: every settings file lists the MCP servers and skill settings the sync adds, updates or removes. Every instructions file shows the lines added and removed. Each file is badged New, Updated or Deleted.
- **Skills grouped per skill**: hundreds of copied skill files show as one row per skill, for example "cloudflare: 320 files removed, Claude Code and Antigravity", with the file list folded away. The 1,112-file Mac sync after RC 10 was this case: deleted skills were removed from `~/.claude/skills` and `~/.gemini/config/skills`, one line per file.
- **A clear choice for each edited file**: for a file changed outside AI Usage, the review shows what changed outside and what AI Usage would write. The choice is **Use AI Usage's version** or **Leave it as it is**, made per file. A file left as it is is not written and stays paused. The rest of the sync still applies.
- `SyncEngine.apply()` accepts `{ overwrite, skip }`; `manager:apply` takes either an id or `{ id, overwrite, skip }`.
