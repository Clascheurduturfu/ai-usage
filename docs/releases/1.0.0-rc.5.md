# AI Usage 1.0.0 RC 5

Release candidate for 1.0.0, after RC 1 (RC 2 to RC 4 were internal builds). It contains everything in the 1.0.0 notes plus the work below.

## In-app updates

Settings → General → **Updates** checks GitHub Releases. Choose **Stable** (finished releases) or **Preview** (the newest prerelease, plus any newer Stable). **Check once a day at launch** only checks; nothing is downloaded or installed until you choose to. A download is verified against GitHub's SHA-256 digest before it can be installed, and the release is checked again just before installation.

- Windows: **Install and restart** runs the installer in passive mode. It closes AI Usage, updates it and opens it again. The installer can replace the MCP relay even while coding clients have it open. Their MCP connections through AI Usage drop while it restarts, as on any restart of AI Usage; reconnect the server in the client or restart the client afterwards.
- macOS: the verified disk image opens; drag AI Usage onto Applications.
- Switching from Preview to Stable never downgrades; the next newer Stable is offered.

Releases are published by the on-demand **Publish release** workflow: Stable from `main`, Preview from `preview`. Preview keeps one current prerelease. Older Preview release records are removed only after the new one is verified, and their tags are kept.

## Command palette

**Ctrl K** (or the sidebar search) opens a palette for pages, your tools, actions (refresh, sync, theme, check for updates), and the shared library. Type a server or skill name to enable, disable or compact it without leaving the page. Any query can also search usage history.

## Context budget

Every coding agent loads MCP tool schemas, a skill index and shared instructions before you type anything. Shared library estimates that always-loaded context per agent, split into MCP tools, skills and instructions, and warns above a limit you choose (30k tokens by default). The heaviest servers are listed with one-click **Compact** and **Disable**.

Servers that cost at least 5k tokens and had no relayed tool call for 30 days are suggested for disabling. Suggestions start only after 30 days of tracking, so a new installation flags nothing. **Keep** hides a suggestion for 30 days on this device.

## Enable or disable everywhere

Each MCP server and skill has an **Enabled** switch. Turning a server off removes it from every synced agent; its definition, recipe and sign-ins are kept. A disabled skill moves to `~/.agents/skills-disabled`, so every client stops loading it, including clients that read the shared folder directly (Cursor, Cline, ZCode, Copilot CLI). Turning it on moves it back. Sharing still publishes disabled skills.

## Claude Code skills

Claude Code reads `~/.claude/skills`, not the shared folder, so it never saw shared skills. Sync now copies the enabled shared skills there, as it already did for Antigravity.

## Compact tool lists

A server with many tools (REA lists about 170, roughly 110k tokens of schemas) can be switched to **Compact**. Eager clients then see two tools: `<server>_search_tools`, whose description names every tool and returns the schemas of matches, and `<server>_call_tool`, which runs one of them unchanged. Claude Code and Antigravity already load tool schemas on demand and keep the full list. Compact needs AI Usage to relay the server: local servers always are; remote servers need Connect via AI Usage.

## Tool call counts

Each MCP card shows its tool count, estimated schema tokens and the number of tool calls relayed through AI Usage, including failures, with the most used tools. Only tool names and counts are stored, never arguments or results.

## Built-in SQLite

The usage database now uses Node's built-in `node:sqlite` instead of the native better-sqlite3 module. Builds no longer depend on matching the build machine's Node version to a compiled addon. Existing databases open unchanged.

## Clearer sync

Shared library → Sync now opens with one status: agents in sync, or sync paused. When a file was edited outside AI Usage it says which file, why sync stopped and that sign-ins are unaffected. The review lists the files that need your decision first, each with **Open file**, then the ones that are ready. **Keep the outside edits and continue** accepts those files as they are and shows what will be written before anything changes. **Undo last sync** replaces Restore last sync and says what it puts back. A file that needs your decision lists what changed in it since the last sync: which MCP server or skill setting was added, removed or edited, by field name. Values that can hold secrets (environment variables, headers, arguments, URLs) are never shown. Keeping the outside edits now lifts the paused status straight away.
